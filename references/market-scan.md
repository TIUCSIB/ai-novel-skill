# 扫榜选材与选题决策(Market Scan)

阶段 0 立项前的市场输入。**核心信念:单本排名只是线索,多榜单、多作品的重复模式才支持趋势判断;扫榜的目的是找到"你能写的爆款方向",不是罗列热门。**

## 一、数据源三级(按优先级)

| 优先级 | 模式 | 怎么拿 | 何时用 |
|---|---|---|---|
| 1 | **用户提供** | 用户粘贴榜单文字/截图,或给现成榜单文件 | 默认最可靠;番茄/起点有反爬,直接抓常拿不到 |
| 2 | **agent 抓取** | 宿主有联网/浏览器工具时,抓公开榜单页(起点排行榜、番茄新书榜等),按下方格式整理 | 用户没现成数据、宿主能联网时 |
| 3 | **内置知识** | 只用历史题材候选做分析 | 拿不到任何实时数据时 |

**内置知识模式的报告开头必须写:"以下分析基于历史题材候选,未经实时榜单校验,只能作为待验证假设",并列出需要复扫的榜单。** 不编造"今天起点畅销榜第一名是 X"这种具体排名。

## 二、榜单文件格式(与采集数据统一口径)

整理或落盘时一律用这个格式,存进本次扫榜目录 `扫榜/{YYYYMMDD}/`(同日再扫加 `-2`,不往旧目录追加——聚合会混进旧榜):

```markdown
# {平台} · {榜单名}

- 抓取时间:{YYYY-MM-DD}
- 数据质量:{脚本采集 | 作者提供 | 手动整理}

### #{排名} {书名}
*{作者} · {题材} · {状态} · {字数} · {热度数字+口径}*
**标签:** {标签1}、{标签2}

> {简介,可选,≤100 字}
```

- **元信息行字段按位置识别**:第一格作者、第二格题材,顺序不能变。截图没作者用 `佚名` 占位,**不能写"未知"**——聚合会把题材错认成作者。
- **热度写"数字+口径"**(`2.3万收藏`、`8000赞同`、`5.1万在读`),一份文件只用一种口径;口径不同的榜分文件存。
- 状态/字数/标签/简介缺了直接省略,不要编。
- 平台名只用:起点 / 番茄 / 晋江 / 七猫 / 刺猬猫 / 知乎盐言(才能和脚本数据合并)。

各平台热度口径不同:番茄看在读,起点看月票/畅销/总推荐,晋江看收藏/营养液/积分,七猫看热度。**完读率、追读、订阅转化是作者后台数据,采集拿不到,用户没提供就不下结论。**

## 三、扫榜流程(五阶段)

### Phase 1 确认平台与方向
沿用用户已给条件,缺的一次问齐(给选项):平台(起点/番茄/晋江/七猫/多平台对比)、频道(男频/女频/都看,番茄七猫才分)、看什么(新书冒头的→多采新书样本 / 成熟大盘→只采默认榜)、有没有关注方向(没有就做全榜概览)。

### Phase 2 确定数据来源
按上表选模式。产出整理好的榜单文件放进 `{outdir}`。

### Phase 3 聚合(确定性)
```
python <技能目录>/scripts/scan_rank.py "{扫榜目录}" --out "{扫榜目录}/扫榜聚合.md"
```
**主会话先只读聚合表,别逐本读原始榜单**:题材分布、去重本数、热度中位、字数中位、标签热词、书名常见词、多榜重合、代表作。看聚合的"采集情况/警告":数据稀疏、混口径的榜单在报告里说明"结论不含它"或降一档可信度。

要看某方向的细节再抽样:`python <技能目录>/scripts/scan_rank.py "{扫榜目录}" --sample {题材或标签或书名} --n 5`,一次一个方向。

上次 `扫榜/{日期}/扫榜聚合.json` 存在时加 `--prev` 自动算趋势(本数Δ/热度中位Δ)。

### Phase 4 数据分析(读聚合后的模式)
1. **题材分布**:本数、占比、热度中位。番茄按题材等额采样,本数是采样上限,冷热看热度中位。
2. **新题材信号**:新书榜样本与多榜重合;无上期就不写涨跌,写"未比较"。
3. **头部老书**:字数几百万、连载多年的代表存量读者,不代表现在开新书能起——判断新方向以新书榜/书库新书为主。
4. **经典题材动态**:老牌题材升/稳/降,没上期只写现状。
5. **字数**:分布与各题材中位(给目标字数定锚)。
6. **书名模式 + 简介卖点**:常见词、标签热词(开头怎么写留给拆文)。

### Phase 5 输出扫榜报告 + 落盘
报告讲"本次样本支持的结论 + 用户能写的方向";脚本名/命令/采集状态不进正文。报告同时写进 `{outdir}/选题决策.md`(不存在就按下面模板建文件头,把报告作为"扫榜结论"一节;已有同名一节整节替换)。**用户只扫榜不选题,结论也已落盘。**

```md
# 选题决策:{平台/方向}
- 扫榜日期:{YYYYMMDD}
- 数据来源:{榜单文件名 / 内置知识}
- 聚合表:{扫榜聚合.md / 无}

## 扫榜结论:{平台}
{Phase 4 报告:市场概况(核心发现一句话)/ 题材热度排行表 / 新题材信号 /
 经典题材动态 / 新元素提取(新人物设定·新切入设定·新桥段)/ 关键数据洞察
 (字数区间·书名特征·标签热词)/ 值得关注的方向 1-3 / 一句话结论}

## 推荐选题
### 选题 1:{一句话方向}
- 题材组合:{主类型 + 副类型/梗}
- 目标读者:{频道 + 熟不熟这类套路}
- 核心卖点:{读者为什么追}
- 能爆的原因:{哪种结构/梗/人设吸引目标读者}(假设,`待拆文验证`)
- 差异化定位:{和榜上现有的不同在哪}
- 可行性:高/中/低 — {理由,写清同方向几本 + 趋势}
- 失败风险:{最可能崩在哪}
- 验证动作:{开写前怎么低成本验证,通常是先写黄金三章看追读}
- 建议拆的对标书:《书名》(平台,选它的理由:优先同方向新书榜里字数不多的)
- 篇幅/平台:{建议字数区间 + 目标平台}
```

## 四、选题四步(每个推荐选题都走完)
1. **能爆的原因(先当假设)**:从重复样本与新元素推测,标 `待拆文验证`,交给拆文回填。
2. **市场验证**:同方向本数、热度、趋势。**最高给"中"**:数据稀疏、首次扫榜无上期、内置知识模式都封顶"中"。
3. **差异化定位**:用户优势 × 市场缺口 = 你的版本不同在哪。没差异化 = 同质化挤不进,降可行性。
4. **可行性 + 风险 + 验证动作**:高(同方向样本足且趋势好 + 素材撑得住 + 有差异化)/ 中(可写先验证)/ 低(素材撑不住或平台不符)。

## 五、与主流程衔接
- 扫榜报告落盘即阶段 0 的输入:`material/genre-research.md` 可从它派生。
- 想确认"能爆的原因"→ 准备好对标书原文(TXT),走 `references/teardown-deep.md` 拆文,拆完回填该选题的依据。
- 定方向后 → SKILL.md 阶段 0 第 2 步 `init_project.py` 建项目;把"扫榜结论 + 选题 X 的差异化定位"写进 `premise.md` 与 `outline/compass.md`。
- 2-3 个选题为宜,按可行性排序,同级时同方向新书样本多的在前。
