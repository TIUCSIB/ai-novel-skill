# 任务级模型路由(Model Routing)

技能本身不强制模型 —— 主创作跑在宿主会话模型上。本文档回答一个实际问题:**哪些子任务值得派 subagent 并指定更便宜/更快的模型,哪些必须用强模型。**

## 原则

1. **创意密度决定模型档位**:需要"写出好句子、好点子"的任务用强模型;需要"按规范提取、按清单核对"的任务,中档模型足够,且往往更稳(不自由发挥)。
2. **质量责任在主代理**:subagent 的产出(analysis/评审报告/提取结果)由主代理核验后落盘;subagent 便宜不等于可以不查。
3. **token 成本大头**:逐章正文阅读(拆书/盲审/审计)和正文生成。前者是纯"读+结构化",最值得降档;后者决定作品质量,不要省。

## 任务路由表

| 任务 | 建议档位 | 理由 | 派发方式 |
|---|---|---|---|
| 立项/compass/弧规划/重写设计 | **强**(宿主模型) | 创意决策,错一步偏全书 | 主代理自己做 |
| 正文起草 | **强**(宿主模型) | 作品核心价值 | 主代理自己做 |
| 七维盲审 | 中档 | 按清单找茬 + 原文举证,规范越硬越不吃模型智力 | Agent 工具派发,可指定中档模型 |
| 拆书逐章提取(analysis) | 中档 | 结构化提取,有 schema 兜底 | 并行 subagent,每 agent 管 5-8 章 |
| 弧末一致性审计 | 中档 | 六类矛盾排查有明确检查面 | Agent 工具派发 |
| 模拟读者 | 中档即可 | 重在"新鲜眼睛"而非智力,换模型反而带来口味差异 | Agent 工具派发(建议与主写模型不同族) |
| 台账回写/上下文组装/检查/导出 | **脚本,零模型** | 确定性逻辑,永远不该花 token | python 脚本 |

## 如何指定

- ZCode 的 Agent 工具支持为 subagent 指定模型(会话内用 `subagent_model`/model 参数;派发模板照常写,prompt 自包含不受模型档位影响);
- 用 ListModels 查看宿主配置了哪些模型及档位,选"同价位中较稳"的;
- 拆书/审计类批量任务,先拿 1 章试跑核对产出质量,再放量并行 —— 中档模型的 schema 遵从度差异要在样本上看。

## 成本护栏(建议习惯)

- 拆书/审计前先估量:章数 × 平均字数 × 模型单价,超过预算先和用户对表;
- 逐章提取失败重试最多 2 次,仍失败就标记跳过并汇报,不要无限重试烧钱;
- 盲审报告超长(说明模型在凑字)或过短(说明没认真读)都退回重审。
