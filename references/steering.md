# 中途干预分诊(Steering)

**何时读**:用户在写作中途提出修改(改设定/改剧情/改角色)时。**先分诊再动手**,绝不凭感觉直接改。

## 分诊表

| 类型 | 判定 | 处理 |
|---|---|---|
| **A 文字级** | 错字、语句、单章内细节 | 直接改;下一章 analysis 备忘;不动台账 |
| **B 设定级** | 战力/世界观/规则变更 | 先 `query_ledger.py -k` 查已写章节是否冲突 → 给用户三选一:**(a) 前向兼容**:新规则自某章起生效、旧章不动,变更记入 bible 与 world_rules;**(b) 回退重写**:受影响章从最早一章起逐章走重写流程;**(c) 放弃变更** |
| **C 剧情级** | 后续走向变更 | 只影响未写章节:经用户确认后更新 compass/弧细纲再继续;若与已写内容矛盾,按 B 类处理 |
| **D 角色级** | 性格/关系/生死大改 | `query_ledger.py -c 角色` 列出场史与状态(可加 `--at N` 查时点),评估波及面 → 与用户确认"前向演进"或"重写相关章",再动台账 |

## 波及面评估怎么查

- 角色:`query_ledger.py -c 名字`(出场史/当前状态/关系)+ `-c 名字 --at N`(某章末状态);
- 设定/道具/地点:`-k 关键词`、`-i 道具`、`-l 地点`;
- 伏笔连带:`-t 伏笔名`;组织归属:`ledger/organizations.json` 是否已有该势力入账;
- 对照已写正文:新设定与原文是否**硬矛盾**(需要回改)还是**兼容**(旧文本可追认为伏笔/破绽,前向解释即可)——兼容则优先前向演进,零回改成本。

## 铁律

- **干预只做用户授权范围内的事**,不顺手"优化"其他内容(发现的无关异常:记录、报告,不动手);
- 已写正文的修改必须走重写流程(改正文 → 重新审校 → 重写 analysis → `apply_analysis.py N --replace`),禁止直接手改台账"圆谎";
- 分诊结论与用户选择记入当前/下一章 analysis 的 `issues_next`,保证下一章知情;
- **B/C/D 类分诊结论一律用 `log_decision.py --type steering` 落盘**(`ledger/decisions.jsonl`),写崩了能回看当时为什么这么决定;
- 三选一必须各写清代价,并给出推荐与理由;用户没拍板之前,正文与台账一律不动。
