# 七维审校 rubric(带反通胀校准)

每章正文完成后执行独立审校,报告写 `reviews/NNN.md`。**审校必须切换到"铁面责编"视角:你的职责是找问题,不是夸作者。**无原文举证的评审视为无效报告。

> 为什么需要校准:同一模型自审自己的稿件天然倾向于打高分。如果连续多章得分都在 95+,说明审校已经失效,回到本文档重读"强制发现"与"分数锚定"两节。

## 一、七维雷达与分值

满分 100。**任何带【红线】的维度不合格,无论总分多高直接 REWRITE。**

| 维度 | 满分 | 重点 | 红线 |
|---|---|---|---|
| D1 设定一致性 | 15 | 能力/道具/规则是否超越当前境界或违背 `world_rules.json`、`bible/rules.md`;**能力使用是否有符合设定的消耗/冷却(体力/资源/修为),且使用后状态账已更新** | ✅ 战力倒挂、违背硬规则 |
| D2 角色行为契合 | 15 | 口吻是否符合台账 voice;配角行动是否有动机;**行动是否受当前伤势/体力/修为限制(身体状态与行动一致)** | ✅ 降智、圣母、人设崩塌 |
| D3 情节张力节奏 | 15 | 说明性叙事是否过长;信息释放与冲突是否符合弧线节奏 | — |
| D4 叙事连贯 | 15 | 开头是否接住上章末尾;时间/位移/伤势是否符合因果。**逻辑专项:① 巧合限额 —— 全章最多一个巧合,且推动危机的巧合必须让局面更糟;② 反派信息面 —— 反派决策只能用其可知信息(对照 timeline 认知),不得全知;③ 可行性 —— 行动方案在 power_matrix/资源/时间/距离约束下成立。行动依据四查:⑴ 行动依据(动机/信息面在台账与前文可回溯)⑵ 执行条件(当前伤势/体力/修为/资源是否支持该行动)⑶ 使用后消耗与后果(是否写进正文并入库)⑷ 关键现实机制(物理/化学/医学)是否查证或标 [待核]** | ✅ 关键转折靠巧合且局面变好;反派未卜先知 |
| D5 伏笔响应 | 10 | 是否执行了章计划的伏笔操作;有无无头线索;**信息控制核验:是否泄露"必须隐藏"的内容;术语泄露核验:未揭示术语(context_pack 术语卡列出的)在正文的表述是否超出其 brief —— 提前展开完整真相同按泄密处理** | ✅ 泄露必须隐藏的真相或提前揭术语 truth(D5 记 0 且结论不得 PASS) |
| D6 章末钩子 | 10 | 对照章计划的钩子设计与引子式;落点是否在危机/揭秘/转折;连续两章是否同型/同式(型与式对照 `references/hooks.md`) | — |
| D7 文学质感与通俗度 | 20 | 5 子项各 4 分:描写质感 / Show don't tell / 对话区分度 / 用词精练与读者理解成本 / 情感打动力;**对照 `references/ai-taste.md`、`references/reader-clarity.md` 与 `style_stats.py` 报告(含段落级碎句堆叠)**;**核验章计划「人味意图」与「概念与信息呈现」(见下)** | — |

### D7 的人味意图核验(必做,逐项举证;弧级判断)

对照章计划的「人味意图」(按本章功能推荐 0-3 项 + 豁免理由)与弧细纲的「人味分布」逐项核验:

| 类目 | 核验标准 |
|---|---|
| 非情节功能细节 | 找得出**不推情节但改善环境质感/人物感受/生活真实感/情绪留白之一**的细节。若本章所有细节都在服务情节/伏笔 → 看本弧内由哪章承担;若细节四样都不改善、纯为凑配额存在 → **[必须修改](建议删除)** |
| 对话失败 | 有一次交流没能完成(打断/说一半/答非所问/说不出话)。本章没有 → 看本弧分布;高潮对决章允许整章不取 |
| 未闭合线头 | 有本章不解释、短期不打算解释的东西。所有疑问都在章内解释干净 → 同上 |
| 主角代价 | 主角有实质损失(物质/关系/声誉/信念)。全章只有收获 → 缺项。**升级章/打脸章/结算章必含;文戏章可由失误/损耗/关系摩擦承担或延后** |

**分布规则(弧级,不要求每章全齐)**:每弧至少各有 1 处对话失败、1 处未闭合线头、1 处主角代价(对照 arc-N.md 的人味分布行核验;连续两弧同类全缺 → [必须修改])。审校报告须说明:本章取/豁免了哪几类、理由、弧内由哪一章承担。**核心红线是反向的:为凑配额机械加戏、为制造失败而失败、代价与前文人设/规则冲突的,一律按 [必须修改] 处理 —— 缺项可以豁免,凑数不能。**

**另查「全员同声」**:抽 2-3 个不同社会背景的角色(文盲/莽夫/文人/上位者),核对他们的句子长度、用词层级、成语密度是否匹配其身份。**底层角色说工整对仗的金句,是最难被词表发现、也最致命的 AI 味。** 判定依据可参考 `taste_audit.py` 第五节的「角色声音指纹」表(句长/感叹率/书面词密度是否分层)。

**语言落地与通俗度五查**(对照 `references/folk-speech.md`、`references/reader-clarity.md`、`craft.md §10` 与 voice.md 的「语言落地」设定):
1. **方言一致性** —— 该说方言的角色说了吗、浓度守不守 voice.md 定的档、有没有把方言当喜剧滤镜堆砌或浓度忽高忽低(人设漂移);
2. **梗的发放与时效** —— 梗有没有按年龄/职业发给对的人、一章是否 ≤2 处、有没有用了台账没登记或超出故事年代的梗(`ledger/terms.json` 的梗条目查得到出处年份)、有没有在正文解释梗(解释=破功);**分两层看**:摄像机层(环境/动作/转场的客观叙述)冒网络语=作者出镜,该收;**脑内层(自由间接引语,角色没说出口的念头直接进句子)恰恰该有梗、有碎语、有脏话** —— 反过来,把内心写成"评估/权衡/系数"这类条理分析报告=术语感过重,是本维度最该抓的假(别只盯着"没梗",要盯"内心不像那个人在想事");
3. **词汇上限(叙述越权)** —— 对照 `style_stats` 的「叙述层黑话」告警逐条判:那词是叙述越权(角色说不出却替他写了),还是戏内人真用的黑话?专业/机构词只该在懂它的人嘴里,不该从叙述层冒出来。**这一条最隐蔽也最致命**,因为它读起来"通顺",只是不像那个人在想事。
4. **知识配额(硬设定题材专查,craft §10)** —— 先对照章计划「概念与信息呈现」行块:每个新概念的呈现是否落在计划承诺的画面/命名时机上;承诺"改变决定"的是否真的改变了(没改变=D7 扣分并列入整改)。再对照 `style_stats` 的「科技术语密度」「机制复述」告警逐条判:删掉这个术语,画面和决定少了吗(没少=装饰)?一段里拆解是否 ≤1 处且落在"只有她能看见"的细节上?术语后有没有紧跟一个删了它就不成立的事实?**先给感受再解剖一遍的(冷。那是……的冰冷。)整段删第二半。** 脑内层的术语是角色的方言,合法 —— 别反向矫枉过正成"禁科学词"。
5. **独立读者理解检查(可读性与改写,reader-clarity)** —— 审校者必须以普通读者视角审读:① 读者能否用白话复述本章核心动作与主角意图?② 是否存在抽象名词堆叠、先上原理课再演戏、或必须反复阅读才能理解的绕口推导?③ 若删掉本章某些术语，画面与剧情是否依然完整?发现理解障碍时，**必须引用原文、指出根因、并给出通俗化改写版本**，说明是否影响设定/因果。杜绝仅写“术语较多”“表达晦涩”等空泛评价。

## 二、机械前置检查(先跑,扣分自动生效)

审校**开始前**先运行 `check_ledger.py`,其结果直接折算进分数,不给审校者讨价还价的余地:

| 机械结果 | 自动扣减 |
|---|---|
| 黑名单命中(每处) | D7 −2 |
| 字数低于下限 85% | D3 直接 ≤10 |
| 字数超上限 150% | D3 −3 |
| ERROR 级台账不一致 | 对应维度为 0,该维度若是红线维度 → REWRITE |

## 三、强制发现(反通胀核心)

1. **每份评审必须列出至少 2 条"[必须修改]"项**,每条带原文摘录与修改方向。
2. **列不出 2 条,总分封顶 90** —— 一章 3000 字的正文不可能毫无可改进处;找不出 2 条只说明审得不够细,回去逐段重读。
3. **引用章计划**:对照 `outline/chapter-NNN.md`,逐一核验节拍是否全数执行、计划的钩子与实际钩子是否一致;计划外的新增桥段要评估是否带偏弧线。
4. **信息控制核验**:对照章计划的四字段(读者已知 / 主角已知 / 必须隐藏 / 可暗示)—— 叙述中泄露"必须隐藏"内容、或视角人物说出不该知道的信息,记入整改清单并按红线处理。
5. **通俗度与理解成本**:若本章正文存在严重“机制复述”（先给感受再解剖原理）或大量未转化为生活经验的纯抽象概念导致读者出戏，必须将该处列入“[必须修改]”清单并给出改写范例；若因此影响全章主干理解，D7 对应子项不得超过 2 分。
6. **行动与状态核验(D4 四查)**:对照 `ledger/characters.json` 的 `state`(condition/资源)、`bible/power_matrix.md`、`timeline.jsonl`(时间账)逐条核验本章主要行动:行动依据是否可回溯、身体状态是否支持、能力消耗是否入账、关键现实机制是否查证。发现"带伤全力死磕""三天不眠连续夜战""重伤次日痊愈如初"类冲突,列入 [必须修改]。
7. 空洞肯定语("写得很棒""完全符合要求")不计分,出现即视为本维度未审。

## 四、分数锚定

| 分数段 | 含义(必须能说出对应证据) |
|---|---|
| 98-100 | 几乎逐句无可挑剔,可直接作为范文片段。**每 10 章至多允许出现 1 章。** |
| 90-97 | 优秀,存在句段级可打磨处,无结构问题。 |
| 80-89 | 合格,有明显可改进项但不影响追读。 |
| 70-79 | 有结构性瑕疵(节奏塌陷/衔接生硬/钩子乏力),建议 POLISH。 |
| <70 或触红线 | REWRITE。 |

## 六、审校后的去向

- **任何含 [必须修改] 项的结论(即使总分 ≥80)都先整改再定稿**:按清单逐条改(只动被警告覆盖的句段,遵守 ai-taste 改写禁区)→ 逐条填「改后原文/复核证据」列 → 重跑 `style_stats.py --chapter N` 与 `rules_guide.py scan --chapter N` 确认落点消失且未引入新警告 → 必要时重新给分;
- PASS(整改后 ≥80 且无未解决 [必须修改])→ 进入分析回写(apply_analysis)→ 闸门汇报;
- POLISH → 只做整改清单里的局部修改,复检清单项后重新给分;
- REWRITE → 对照缺陷清单重构本章(重写后重复整个审校,不得跳过);
- 重写两次仍 <80:停下来向用户说明问题与可能的根因(设定冲突?弧线设计问题?身体状态账没对?),不要无脑试第三遍。

### 字数不足时的扩写诊断(防注水四问)

机械检查报"字数低于下限"后,**先诊断再扩**,禁止直接堆环境描写/心理独白凑字:

| 诊断 | 症状 | 扩法 |
|---|---|---|
| 场景薄 | 有事件无过程,一章读完没画面 | 进场晚出场早:把转述改现场,补一处非视觉感官 |
| 跳跃快 | 节拍之间没过渡,情绪没长出来 | 在两个节拍之间加一个"是的,但是"回合 |
| 情感平 | 该心疼的地方读者无感 | 挑一件具体的小物证写前后对比,不用形容词 |
| 事件少 | 节拍本身不够数 | 加一个服务人物关系的小对手戏(不为注水而加) |
| 对话干瘪 | 你一句我一句无交锋 | 加一次打断/答非所问(顺手补上对话失败类意图) |

**注水判定一问**:删掉拟新增的这段,本章是否变差?不变差就不要加。

## 七、独立盲审(推荐:派 subagent 根治自审通胀)

同一上下文里自己审自己,天然手软 —— 这是"26 章全是 92-100 分"的根因。条件允许时,**用任务派发工具(如 ZCode 的 Agent 工具)派一个未参与写作的子代理盲审**:它没看过写作过程,没有沉没成本,挑刺不客气。

派发 prompt 模板(自包含,把 `<技能目录>`/`<项目目录>`/`N` 替换为实际值):

```text
你是铁面责编,负责审校一部长篇小说的第 N 章。你没有参与写作,只依据文件证据工作,职责是找问题而不是夸作者:

1. 读审校标准:<技能目录>/references/review-rubric.md(含机械扣分、强制发现、分数锚定,必须遵守)
2. 读被审正文:<项目目录>/chapters/NNN.md
3. 读核对依据:
   - <项目目录>/outline/chapter-NNN.md(节拍/信息控制四字段/人味意图/概念与信息呈现/引子式与钩子型/钩子设计)
   - <项目目录>/ledger/characters.json、foreshadowing.json、world_rules.json、organizations.json、terms.json、timeline.jsonl(行动依据四查用:依据可回溯/身体状态支持/消耗入账/时间账;术语:未揭示词的 brief 是允许信息上限,正文超出即 D5 红线)
   - <项目目录>/bible/power_matrix.md、bible/rules.md(战力红线与禁写事项;行动可行性、越级代价、能力消耗)
   - 规则库扫描:<技能目录>/scripts/rules_guide.py scan <项目目录> --chapter N(命中行号与改写方向;你据此核 D7 用词)
   - 机械体检:<技能目录>/scripts/style_stats.py <项目目录> --chapter N(句长/碎句堆叠/人味代标/概念负担告警;作为线索,不得替代你自己的语义判断)
   - 上一章结尾:<项目目录>/chapters/(N-1).md 的末尾 500 字(衔接核验)
4. 按七维逐项打分并原文举证;先对照 rubric 第二节做机械扣分;至少列出 2 条带原文摘录的[必须修改](每条另给 改后原文/处理 建议);对照信息控制四字段查泄密;对照 D4 行动依据四查与 D7 人味意图核验。
5. 只输出 rubric 第五节格式的完整评审报告,不要输出其他内容。
```

主代理收到报告后:原样写入 `reviews/NNN.md`,按结论执行(PASS/POLISH/REWRITE)。**不得以"我写作时有考虑"为由驳回或软化报告**;对报告有异议,向用户说明而不是自行改分。无法派发子代理时才降级为主代理自审,并自觉执行"强制发现"与"分数锚定"条款。
