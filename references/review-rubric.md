# 七维审校 rubric(带反通胀校准)

每章正文完成后执行独立审校,报告写 `reviews/NNN.md`。**审校必须切换到"铁面责编"视角:你的职责是找问题,不是夸作者。**无原文举证的评审视为无效报告。

> 为什么需要校准:同一模型自审自己的稿件天然倾向于打高分。如果连续多章得分都在 95+,说明审校已经失效,回到本文档重读"强制发现"与"分数锚定"两节。

## 一、七维雷达与分值

满分 100。**任何带【红线】的维度不合格,无论总分多高直接 REWRITE。**

| 维度 | 满分 | 重点 | 红线 |
|---|---|---|---|
| D1 设定一致性 | 15 | 能力/道具/规则是否超越当前境界或违背 `world_rules.json`、`bible/rules.md` | ✅ 战力倒挂、违背硬规则 |
| D2 角色行为契合 | 15 | 口吻是否符合台账 voice;配角行动是否有动机 | ✅ 降智、圣母、人设崩塌 |
| D3 情节张力节奏 | 15 | 说明性叙事是否过长;信息释放与冲突是否符合弧线节奏 | — |
| D4 叙事连贯 | 15 | 开头是否接住上章末尾;时间/位移/伤势是否符合因果。**逻辑专项:① 巧合限额 —— 全章最多一个巧合,且推动危机的巧合必须让局面更糟;② 反派信息面 —— 反派决策只能用其可知信息(对照 timeline 认知),不得全知;③ 可行性 —— 行动方案在 power_matrix/资源/时间/距离约束下成立** | ✅ 关键转折靠巧合且局面变好;反派未卜先知 |
| D5 伏笔响应 | 10 | 是否执行了章计划的伏笔操作;有无无头线索;**信息控制核验:是否泄露"必须隐藏"的内容;术语泄露核验:未揭示术语(context_pack 术语卡列出的)在正文的表述是否超出其 brief —— 提前展开完整真相同按泄密处理** | ✅ 泄露必须隐藏的真相或提前揭术语 truth(D5 记 0 且结论不得 PASS) |
| D6 章末钩子 | 10 | 对照章计划的钩子设计与引子式;落点是否在危机/揭秘/转折;连续两章是否同型/同式(型与式对照 `references/hooks.md`) | — |
| D7 文学质感 | 20 | 5 子项各 4 分:描写质感 / Show don't tell / 对话区分度 / 用词精练 / 情感打动力;**对照 `references/ai-taste.md` 的对比例句抓套路,对照 `style_stats.py` 的密度/口头禅/绕行报告**;**核验章计划「人味配额」四项是否逐项落实(见下)** | — |

### D7 的人味配额核验(必做,逐项举证)

对照章计划的「人味配额」四项,每项给出正文原文举证,缺项须说明理由:

| 项 | 核验标准 |
|---|---|
| 无用细节 | 找得出与主线无关、也不埋任何伏笔的细节。若本章所有细节都在服务情节/伏笔 → 缺项 |
| 对话失败 | 有一次交流没能完成(打断/说一半/答非所问/说不出话)。全章对话都成功传递了信息 → 缺项 |
| 未闭合线头 | 有本章不解释、短期不打算解释的东西。所有疑问都在章内解释干净 → 缺项 |
| 主角代价 | 主角有实质损失(物质/关系/声誉/信念)。全章只有收获 → 缺项。**升级章/打脸章重点查** |

**另查「全员同声」**:抽 2-3 个不同社会背景的角色(文盲/莽夫/文人/上位者),核对他们的句子长度、用词层级、成语密度是否匹配其身份。**底层角色说工整对仗的金句,是最难被词表发现、也最致命的 AI 味。** 判定依据可参考 `taste_audit.py` 第五节的「角色声音指纹」表(句长/感叹率/书面词密度是否分层)。

**语言落地四查**(对照 `references/folk-speech.md`、`craft.md §10` 与 voice.md 的「语言落地」设定):
1. **方言一致性** —— 该说方言的角色说了吗、浓度守不守 voice.md 定的档、有没有把方言当喜剧滤镜堆砌或浓度忽高忽低(人设漂移);
2. **梗的发放与时效** —— 梗有没有按年龄/职业发给对的人、一章是否 ≤2 处、有没有用了台账没登记或超出故事年代的梗(`ledger/terms.json` 的梗条目查得到出处年份)、有没有在正文解释梗(解释=破功);**分两层看**:摄像机层(环境/动作/转场的客观叙述)冒网络语=作者出镜,该收;**脑内层(自由间接引语,角色没说出口的念头直接进句子)恰恰该有梗、有碎语、有脏话** —— 反过来,把内心写成"评估/权衡/系数"这类条理分析报告=术语感过重,是本维度最该抓的假(别只盯着"没梗",要盯"内心不像那个人在想事");
3. **词汇上限(叙述越权)** —— 对照 `style_stats` 的「叙述层黑话」告警逐条判:那词是叙述越权(角色说不出却替他写了),还是戏内人真用的黑话?专业/机构词只该在懂它的人嘴里,不该从叙述层冒出来。**这一条最隐蔽也最致命**,因为它读起来"通顺",只是不像那个人在想事。
4. **知识配额(硬设定题材专查,craft §10)** —— 对照 `style_stats` 的「科技术语密度」「机制复述」告警逐条判:删掉这个术语,画面和决定少了吗(没少=装饰)?一段里拆解是否 ≤1 处且落在"只有她能看见"的细节上?术语后有没有紧跟一个删了它就不成立的事实?**先给感受再解剖一遍的(冷。那是……的冰冷。)整段删第二半。** 脑内层的术语是角色的方言,合法 —— 别反向矫枉过正成"禁科学词"。

## 二、机械前置检查(先跑,扣分自动生效)

审校**开始前**先运行 `check_ledger.py`,其结果直接折算进分数,不给审校者讨价还价的余地:

| 机械结果 | 自动扣减 |
|---|---|
| 黑名单命中(每处) | D7 −2 |
| 字数低于下限 85% | D3 直接 ≤10 |
| 字数超上限 150% | D3 −3 |
| ERROR 级台账不一致 | 对应维度为 0,该维度若是红线维度 → REWRITE |

## 三、强制发现(反通胀核心)

1. **每份评审必须列出至少 2 条"[必须修改]"项**,每条带原文摘录与修改方向。
2. **列不出 2 条,总分封顶 90** —— 一章 3000 字的正文不可能毫无可改进处;找不出 2 条只说明审得不够细,回去逐段重读。
3. **引用章计划**:对照 `outline/chapter-NNN.md`,逐一核验节拍是否全数执行、计划的钩子与实际钩子是否一致;计划外的新增桥段要评估是否带偏弧线。
4. **信息控制核验**:对照章计划的四字段(读者已知 / 主角已知 / 必须隐藏 / 可暗示)—— 叙述中泄露"必须隐藏"内容、或视角人物说出不该知道的信息,记入整改清单并按红线处理。
5. 空洞肯定语("写得很棒""完全符合要求")不计分,出现即视为本维度未审。

## 四、分数锚定

| 分数段 | 含义(必须能说出对应证据) |
|---|---|
| 98-100 | 几乎逐句无可挑剔,可直接作为范文片段。**每 10 章至多允许出现 1 章。** |
| 90-97 | 优秀,存在句段级可打磨处,无结构问题。 |
| 80-89 | 合格,有明显可改进项但不影响追读。 |
| 70-79 | 有结构性瑕疵(节奏塌陷/衔接生硬/钩子乏力),建议 POLISH。 |
| <70 或触红线 | REWRITE。 |

## 五、评审报告格式

```markdown
# 章节评审:第 N 章 《标题》
* 得分:XX / 100(机械扣分已计入:黑名单 x 处 −y)
* 结论:[ ] PASS(≥80) | [ ] POLISH(60-79) | [ ] REWRITE(<60 或红线)

### 七维逐项
#### D1 设定一致性(得分 /15)
* 判词:……
* 原文证据:
  > "……"
  【分析】:符合/违背了 world_rules W-00x……
(……D2-D7 同格式;D7 需列 5 子项各自得分与 AI 味检测结果)

### 与章计划的对照
* 节拍执行:1✓ 2✓ 3✓ 4✓(或说明偏差)
* 计划钩子 vs 实际钩子:……
* 伏笔操作核验:F-001 plant ✓(analysis 已登记)

### 整改清单
1. [必须修改]……(带原文引用)
2. [必须修改]……
3. [建议优化]……
```

## 六、审校后的去向

- PASS → 进入分析回写(apply_analysis)→ 闸门汇报;
- POLISH → 只做整改清单里的局部修改,复检清单项后重新给分;
- REWRITE → 对照缺陷清单重构本章(重写后重复整个审校,不得跳过);
- 重写两次仍 <80:停下来向用户说明问题与可能的根因(设定冲突?弧线设计问题?),不要无脑重试第三遍。

### 字数不足时的扩写诊断(防注水四问)

机械检查报"字数低于下限"后,**先诊断再扩**,禁止直接堆环境描写/心理独白凑字:

| 诊断 | 症状 | 扩法 |
|---|---|---|
| 场景薄 | 有事件无过程,一章读完没画面 | 进场晚出场早:把转述改现场,补一处非视觉感官 |
| 跳跃快 | 节拍之间没过渡,情绪没长出来 | 在两个节拍之间加一个"是的,但是"回合 |
| 情感平 | 该心疼的地方读者无感 | 挑一件具体的小物证写前后对比,不用形容词 |
| 事件少 | 节拍本身不够数 | 加一个服务人物关系的小对手戏(不为注水而加) |
| 对话干瘪 | 你一句我一句无交锋 | 加一次打断/答非所问(顺手填对话失败配额) |

**注水判定一问**:删掉拟新增的这段,本章是否变差?不变差就不要加。

## 七、独立盲审(推荐:派 subagent 根治自审通胀)

同一上下文里自己审自己,天然手软 —— 这是"26 章全是 92-100 分"的根因。条件允许时,**用任务派发工具(如 ZCode 的 Agent 工具)派一个未参与写作的子代理盲审**:它没看过写作过程,没有沉没成本,挑刺不客气。

派发 prompt 模板(自包含,把 `<技能目录>`/`<项目目录>`/`N` 替换为实际值):

```text
你是铁面责编,负责审校一部长篇小说的第 N 章。你没有参与写作,只依据文件证据工作,职责是找问题而不是夸作者:

1. 读审校标准:<技能目录>/references/review-rubric.md(含机械扣分、强制发现、分数锚定,必须遵守)
2. 读被审正文:<项目目录>/chapters/NNN.md
3. 读核对依据:
   - <项目目录>/outline/chapter-NNN.md(节拍/信息控制四字段/人味配额/引子式与钩子型/钩子设计)
   - <项目目录>/ledger/characters.json、foreshadowing.json、world_rules.json、organizations.json、terms.json(术语:未揭示词的 brief 是允许信息上限,正文超出即 D5 红线)
   - <项目目录>/bible/power_matrix.md、bible/rules.md(战力红线与禁写事项)
   - 规则库扫描:<技能目录>/scripts/rules_guide.py scan <项目目录> --chapter N(命中行号与改写方向;你据此核 D7 用词)
   - 上一章结尾:<项目目录>/chapters/(N-1).md 的末尾 500 字(衔接核验)
4. 按七维逐项打分并原文举证;先对照 rubric 第二节做机械扣分;至少列出 2 条带原文摘录的[必须修改];对照信息控制四字段查泄密。
5. 只输出 rubric 第五节格式的完整评审报告,不要输出其他内容。
```

主代理收到报告后:原样写入 `reviews/NNN.md`,按结论执行(PASS/POLISH/REWRITE)。**不得以"我写作时有考虑"为由驳回或软化报告**;对报告有异议,向用户说明而不是自行改分。无法派发子代理时才降级为主代理自审,并自觉执行"强制发现"与"分数锚定"条款。
