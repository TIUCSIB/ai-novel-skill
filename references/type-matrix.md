# 章节类型与类型矩阵(Chapter Type Matrix)

**何时读**:写章计划时定 `章节类型`;审校时按类型取重点;弧末审计看类型配比与张力曲线。
**核心原则**:类型不是标签,是本章的"戏剧任务合同" —— 它规定本章**必须发生什么、禁止发生什么、审校先看哪一维**。类型与冲突值、伏笔 Tier、收支账一起,构成章级叙事账;它们不是新的硬配额,而是让"这一章该干什么"在动笔前就可检验。

## 一、六种类型

| 类型 | 本章必须发生 | 本章禁止 | 审校重点 | 动笔前额外读 |
|---|---|---|---|---|
| **推进** | 至少一个情节点改变局面:不可逆决定、新信息、新障碍、新代价 | 纯说明;原地打转;只换场景不换局面 | D3 节奏 / D4 连贯 | 当前弧目标、上一章 `issues_next` |
| **高潮** | 冲突值 4-5 或钩子 L3+;至少一个不可逆后果/代价 | 巧合解围;无代价胜利;连续高潮 | D1 设定 / D2 人物 / D3 节奏 / D6 钩子 | 力量矩阵、资源账、伏笔回收窗口 |
| **过渡** | 关系/世界/情绪至少一项变化,为下一章蓄势 | 回收 Tier-1 主线伏笔;硬塞大冲突 | D3 节奏 / D7 质感 | 人味意图、日常过渡弧模板 |
| **关系** | 至少一对关系发生变化或暴露新面,且用行动/对话演出来 | 关系变化只靠旁白总结;关系章变成主线过场 | D2 人物 / D7 质感 | 双方 voice、关系史、未闭合线头 |
| **线索** | 至少一个伏笔操作或术语首现;章末留下新问题 | 一次解释完所有线索;调查完却没有新问题 | D5 伏笔 / D6 钩子 | 伏笔 Tier、术语卡、相关旧章 |
| **代价** | 一个具体损失(物质/关系/声誉/信念),且影响后续行动 | 只受伤不损失;代价立即被补偿 | D2 人物 / D4 连贯 / D7 质感 | 资源账、伤势、人味意图 |

**类型由"本章的戏剧任务"决定,不由题材决定。** 一章可以同时有打斗和感情,但只能有一个主类型;主类型回答"如果删掉这一章,读者会损失什么"。

## 二、章计划与章分析怎么写

章计划(人写,供动笔):

```markdown
# 第37章 血字请帖

章节类型: 线索
冲突值: 3
钩子DNA: 林昭-收到-请帖-落款死人

节拍:
1. ...
出场角色: 林昭, 老周
伏笔操作: F-001 advance(玉佩与请帖同时反应)
章末钩子: 血字请帖的落款是十年前已死的沈半城(型7信息差 | 强度L3)
```

章分析(写完回写,机器读):

```json
{
  "chapter": 37,
  "type": "线索",
  "conflict": 3,
  "hook_dna": "林昭-收到-请帖-落款死人",
  "gains": [
    {"type": "item", "name": "血字请帖", "major": false, "note": "拿到物证"}
  ],
  "costs": [
    {"type": "relationship", "name": "老周开始怀疑林昭", "major": true,
     "for": "追查请帖", "note": "信任出现裂缝"}
  ]
}
```

字段规则:

- `章节类型` / `type`:六选一;计划与分析必须一致。旧项目可缺省;`book.json` 的 `schema_version >= 2` 时,已完成章缺 `type` 会 WARN。
- `冲突值` / `conflict`:1-5 整数。**1** 日常/无冲突;**2** 小摩擦/信息差;**3** 明确冲突或转折;**4** 大战/重大决裂/高潮;**5** 卷峰/不可逆。它是自评分,不是精确公式;用途是让"这章到底紧不紧"可比较。
- `钩子DNA` / `hook_dna`:3-5 个短词,用 `-` 或 `/` 分隔,描述钩子的**结构**而不是文案。格式建议 `主体-动作-对象-反转`:例 `主角-发现-请帖-死人落款`。相邻章 DNA 高度同构(Jaccard >0.8)会被提示换结构;计划与实际 DNA 漂移(Jaccard <0.3)会 WARN。
- `gains` / `costs`:本章的收支账。`name` 必填;`type` 可选,推荐 `item` / `ability` / `level` / `ally` / `victory` / `status` / `resource` / `injury` / `relationship` / `reputation` / `belief` / `opportunity`;`major` 可省略 —— 省略时按 `type` 推定(`item`/`ability`/`level`/`ally`/`victory`/`status`/`breakthrough`/`treasure`/`power` 视为重大),**显式写 `major: false` 则以你的判断为准**,不再追代价(拿一张纸条、捡一块普通铜牌不该触发顺风车);`entity` 可填角色名/ID;`for` 可填这笔代价对应哪项获得。`apply_analysis` 会把它们追加进 `timeline.jsonl`(type `gain` / `cost`),`--replace` 时随章撤销。

## 三、伏笔 Tier:先定"这条线能活多久"

| Tier | 范围 | 典型 | 休眠阈值 | 建议回收间隔 |
|---|---|---|---|---|
| **T1** | 全书主线 | 身世、终极真相、核心对手、世界规则级秘密 | 35 章 | 跨卷;`min_payoff_spacing` 建议 ≥20 |
| **T2** | 弧/卷线 | 本卷反派、阶段目标、重要配角秘密 | 12 章 | 5-15 章 |
| **T3** | 章级/场景级 | 本章小疑点、道具来历、路人异常 | 4 章 | 1-5 章 |

字段:`tier`(1/2/3)、`scope`(`book`/`arc`/`chapter`,缺省按 Tier 推导)、`cross_volume`(是否跨卷)、`min_payoff_spacing`(埋设到回收的最小章数)。旧账不填 Tier 时沿用原来的 15 章休眠阈值;填了 Tier 就按上表。

**类型 × Tier 的硬约束(脚本只查可机械判定的部分)**:

- **过渡章**不得 `payoff` 一条 T1;T1 回收应放在高潮/卷峰章。
- **线索章**至少要 plant/advance 一条伏笔,或首现一个术语;只调查不收线、也不开新问题,不算线索章。
- **高潮章**可以收 T2/T3;收 T1 时,冲突值应 ≥4 或钩子 L3+,否则降级为推进/过渡。
- **代价章**最适合承担 T1 重大获得的代价;代价必须影响后续行动,不能当章补偿掉。
- **关系章**可以推进 T2/T3 的人物线,但不要把 T1 真相一次性说破。

**配额建议(不是硬阈值)**:全书活跃 T1 建议 ≤5 条;每卷新增 T1 1-3 条;跨卷伏笔至少 1 条在推进。`check_ledger` 会在活跃 T1 >5 或 10 章后仍无活跃 T1 时 WARN。

## 四、类型配比与张力曲线

没有放之四海皆准的比例,但可以用 20 章窗口自检。一个通用参考:

| 类型 | 20 章窗口参考 | 作用 |
|---|---|---|
| 推进 | 8-10 章 | 主线前进 |
| 高潮 | 2-3 章 | 峰值与回收 |
| 过渡 | 3-4 章 | 呼吸、消化、人物生活 |
| 关系 | 2-3 章 | 人物羁绊与声音 |
| 线索 | 2-3 章 | 埋线、调查、抛新问题 |
| 代价 | 1-2 章 | 兑现重量、防止全能主角 |

**节奏纪律**:

- 连续 3 章同一类型(尤其过渡/关系/线索)且无推进/高潮 → 节奏停滞,插一个推进或高潮。
- 每 8-10 章至少一个高潮章;相邻峰值间隔 >8 章,等待感会堆积成弃书点。
- 典型顺序:**线索 → 高潮 → 代价 → 过渡 → 推进**;不是每弧都套,但别让"高潮"之后立刻又是"高潮"。
- `check_ledger` 的张力曲线看 `conflict`:连续 3 章 ≥4 = 高潮疲劳;连续 5 章 ≤2 = 节奏塌陷。`--curve` 打印全书曲线。
- 弧末审计对照本弧的 `章节类型分布` 与 `conflict` 曲线,不要求精确比例,只要求"峰值有间隔、谷底有事发生、过渡不空转"。

## 五、代价守恒(收支账)

这一条针对最常见的"全能主角"病:**主角连续获得,却没有付出任何读者能记住的代价。**

- 每个重大获得(显式 `major: true`,或省略 `major` 但 `type` 属于能力/道具/等级/盟友/胜利/地位一类),必须在**本章或之后 5 章内**至少有一笔 `costs`;否则 `check_ledger` WARN。显式写 `major: false` 的获得不在此列 —— 小物件、情报碎片、临时便利不该被追账。
- 连续 2 章"只有获得、没有代价" → WARN "顺风车";弧末审计必须补代价或改章。
- 代价要具体、可追溯:物质损失、关系破裂、声誉受损、信念动摇、机会失去。**过场伤不算代价**;立刻被补偿的损失也不算。
- 代价不必与获得一一对应,但 `for` 字段能帮助读者和审校看清"这笔账为谁而付"。
- 悲剧/黑暗题材可以"代价先于获得";检查窗口仍从获得章起算,前文已付的代价可在 `note` 里说明,避免机械补账。

## 六、兼容旧项目

- 所有新字段都是**可选增量**:缺失时不报 ERROR,旧项目按原规则运行。
- 新项目 `book.json` 带 `schema_version: 2`;已完成章缺 `type` 会给 WARN,提醒补类型,不影响回写。
- 旧伏笔缺 `tier` 时沿用 15 章休眠阈值;想启用 Tier 检查,给条目补 `tier`/`scope` 即可,不需要迁移脚本。
- 章分析缺 `gains`/`costs` 时不做代价守恒检查;先在新章使用,历史章按弧末审计逐步补。
